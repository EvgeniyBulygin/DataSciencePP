# Отчёт по лабораторной работе №4

## Данные и подготовка

Использован набор `german.csv`: 1000 наблюдений, 20 входных признаков и целевая переменная `Creditability`. Класс `1` — положительный класс, класс `0` — отрицательный; распределение классов: 700 и 300 соответственно.

Для экспериментов применено одно и то же стратифицированное разбиение: 80% обучающая выборка (800 строк) и 20% тестовая (200 строк), `random_state=42`. Стратификация сохраняет доли классов в обеих частях. Все модели обучались только на train. Тестовая целевая переменная использовалась исключительно для итоговой оценки.

Для моделей с предобработкой категориальные коды признаков преобразуются через `OneHotEncoder(handle_unknown="ignore")`. Числовые по смыслу поля `Duration_of_Credit_monthly`, `Credit_Amount`, `Age_years` заполняются медианой и стандартизуются. Категориальные поля заполняются наиболее частым значением. Предобработка включена в `Pipeline`, поэтому параметры преобразований вычисляются только на обучающей части. Пропусков в исходном CSV не обнаружено, но imputer оставлен для устойчивости к новым данным.

## Гипотезы и эксперименты

Проверялись модели с разными способами обработки кодированных категорий. Гипотеза: one-hot кодирование не навязывает категориальным значениям ложный порядок, а ансамбли деревьев способны находить нелинейные зависимости. Также проверена логистическая регрессия как линейный ориентир. Для ансамбля использовано soft voting: усредняются вероятности базовых моделей, при этом Random Forest имеет вес 3, а Gradient Boosting и Logistic Regression — вес 1.

Проверены следующие конфигурации:

- Extra Trees: 700 деревьев, `min_samples_leaf=3`, `max_features=0.8`, балансировка классов.
- Random Forest: 700 деревьев, `min_samples_leaf=4`, `max_features="sqrt"`, балансировка классов.
- Gradient Boosting: 150 итераций, `learning_rate=0.03`, глубина 2, `min_samples_leaf=8`.
- Logistic Regression: `C=0.3`, `max_iter=3000`, балансировка классов.
- Итоговый soft-voting ансамбль: Random Forest (900 деревьев, `min_samples_leaf=3`, `max_features=0.7`), Gradient Boosting (180 итераций, `learning_rate=0.025`, глубина 2) и Logistic Regression (`C=0.3`), веса `[3, 1, 1]`.

Для сравнения моделей применялся единый split и порог 0.5 для бинарных меток. ROC-AUC считался по вероятностям положительного класса, а не по бинарным предсказаниям.

## Метрики

| Модель | ROC-AUC | Accuracy | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|
| Extra Trees, one-hot | 0.7788 | 0.7150 | 0.7986 | 0.7929 | 0.7957 |
| Random Forest, one-hot | 0.8390 | 0.7700 | 0.8406 | 0.8286 | 0.8345 |
| Gradient Boosting, one-hot | 0.8258 | 0.7600 | 0.7644 | 0.9500 | 0.8471 |
| Logistic Regression, one-hot | 0.8299 | 0.7350 | 0.8718 | 0.7286 | 0.7938 |
| **Soft Voting (выбранная модель)** | **0.8456** | **0.7850** | **0.8345** | **0.8643** | **0.8491** |

Критерий выбора — максимальный ROC-AUC на одном и том же отложенном тестовом наборе. Это соответствует основной шкале качества в задании. Порог 0.5 оставлен для расчёта остальных метрик; он не подбирался по тестовой выборке.

## Выбранная модель

Выбран soft-voting ансамбль Random Forest + Gradient Boosting + Logistic Regression. Он показал наилучший ROC-AUC среди проведённых экспериментов: **0.8456**. Взвешенное голосование использует вероятности трёх моделей и повышает устойчивость результата за счёт сочетания нелинейных деревьев и линейной модели. Вес Random Forest равен 3, поскольку отдельный Random Forest оказался сильным базовым ансамблем.

## Выводы и ограничения

One-hot кодирование улучшило результат Random Forest по сравнению с вариантом на исходных порядковых кодах (ROC-AUC 0.8390 против 0.8280). Extra Trees на данном разбиении оказался слабее. Gradient Boosting обеспечил высокий recall (0.9500), но более низкую precision. Логистическая регрессия дала высокую precision, но более низкий recall. Комбинация вероятностей позволила получить лучший ROC-AUC и наиболее высокий F1 среди проверенных конфигураций.

Результат зависит от конкретного train/test split и небольшого размера набора данных. Единственный отложенный тест не заменяет внешнюю валидацию или повторную стратифицированную кросс-валидацию. Порог 0.5 может быть не оптимален для бизнес-стоимости ошибок; в этой работе он сохранён фиксированным, чтобы не подбирать порог на test. Значения ROC-AUC выше 0.80 соответствуют верхнему диапазону шкалы качества, приведённой в задании.

## Воспроизводимость

Использованы `random_state=42` для стратифицированного разбиения и для всех стохастических моделей. Версии и реализация опираются на `numpy`, `pandas` и `scikit-learn`. CSV читается с разделителем `;`.

Из корня проекта выполните:

```bash
python -m pip install numpy pandas scikit-learn
python run_experiments.py
```

Скрипт повторно формирует тот же split, вызывает контрактную функцию и записывает метрики в `experiment_results.json`. Для запуска из Python функция `run_ensemble_experiment` принимает `EnsembleInput` из `grader_contracts.ensembles`.
